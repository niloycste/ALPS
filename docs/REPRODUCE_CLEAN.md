# Clean reproduction

This procedure regenerates the scientific fields used by Tables II--VI and the
data behind the manuscript's three experimental figures. The overview pipeline
is a conceptual illustration. Timing fields are recorded but excluded from
exact comparisons because they depend on the machine and concurrent load.

The artifact contains the expected CSV outputs, four dataset manifests with
SHA-256 hashes, pinned dependency files, and the verification script. Run these
commands from a newly extracted `ALPS/` directory in PowerShell:

```powershell
py -3.13 -m venv .venv-core
.\.venv-core\Scripts\python.exe -m pip install -r config\requirements-core-lock.txt
conda env create -p .\.conda-metis -f config\environment-metis-lock.yml
.\.venv-core\Scripts\python.exe -m tools.verification.verify_clean_environment `
  --metis-python .\.conda-metis\python.exe
```

The command checks the supplied evidence and regenerates:

| Manuscript evidence | Expected artifact data |
|---|---|
| Table II; static sweep figures | `results/all_static.csv` (150 rows, including the log-only locality trace) |
| Table III | `results/all_horizon.csv` (48 rows) |
| Table IV | `results/headtohead.csv` (360 rows) |
| Table V; recall versus scan figure | `results/retrieval_benchmark.csv` (1,140 rows) and `results/retrieval_frontier.csv` (2,604 rows) |
| Table VI | `results/prospective_retrieval*.csv` (48 allocations and 2,688 query rows) |
| Prospective matched-recall figure | `results/prospective_equal_recall_*.csv`, regenerated by `experiments.analyze_prospective_equal_recall` |
| Graph-weight sensitivity | `results/prospective_graph_*.csv` (36 allocations and 2,016 query rows) |
| Receipt audit | 100 cached C1 responses with matching successful Transfer logs |

Success writes `docs/CLEAN_REPRODUCTION.json` with `"status": "passed"`, exact
package versions, and the completed checks. Scientific fields must match
exactly. Allocation and query timings are excluded. The Ethereum receipt files
remain unresolved RPC responses and are not counted as successful or reverted.

The normalization used in Equation (1) has a focused executable audit:

```powershell
.\.venv-core\Scripts\python.exe -m tools.verification.verify_semantic_scale
```

It reconstructs the initial weighted k-means prototypes independently, checks
that the implementation passes all nonzero sender-to-prototype squared
distances to one median call, distinguishes that result from assigned-only
distances, and verifies that `semantic_scale` has one assignment in `alps`.
The recorded result is `docs/SEMANTIC_SCALE_VERIFICATION.json`.

The prospective matched-recall and deployment-scenario analysis is regenerated
without rerunning allocation:

```powershell
.\.venv-core\Scripts\python.exe -m experiments.analyze_prospective_equal_recall
```

It uses only the seven history-frozen plans already present in
`prospective_retrieval.csv`. Interpolation at common achieved recalls is a
descriptive comparison and does not select a deployable plan from suffix data.

Dataset hashes are checked by `tools.prepare_anonymous_artifact` before packaging.
`SHA256SUMS.json` records every packaged file hash, and `LOCAL_CHECKS.json`
records dataset and PDF checks. This is a local clean-environment reproduction
and does not claim independent third-party replication.
